# 回归清单（演示前逐条打勾）

每次演示、每次答辩前，从第 1 条开始走一遍。**任何一条不通，不要上台。**

约定：`✅ 可验` / `⛔ 阻塞（依赖未就绪）` / `☐ 未执行`

---

## 一、六条验收标准

### 1. 两人抢同一座位，只有一个成功

- 状态：✅ 可验
- 怎么做：两个学生账号分别登录，同一时段点同一个座位
- 期望：一个成功，另一个提示「该座位已被预约」
- 证据：截图 + 数据库 `SELECT COUNT(*) FROM reservation WHERE active_seat_id IS NOT NULL AND slot_start = ?` = 1
- 结果：☐

### 2. 签到后状态变成「使用中」

- 状态：✅ 可验（接口层）；界面部分 ⛔ 等客户端
- 怎么做：预约后输入座位上的座位码签到
- 期望：状态变 CHECKED_IN，记录签到时间
- 证据：`SELECT status, checked_in_at FROM reservation WHERE id = ?`
- 结果：☐

### 3. 不签到，到点自动释放并扣 10 分（只扣一次）

- 状态：⛔ **阻塞**（守护节点未提交）
- 解除条件：`seatkeeper-guardian` 能独立启动并每 30 秒调一次 `expire-batch`
- 期望：状态 EXPIRED、座位可再约、信用 -10、`credit_log` 只有 1 条
- 结果：☐

### 4. 停网关 2 分钟，预约和释放照常，恢复后补投

- 状态：⛔ **阻塞**（网关只有探针，没有投递实现）
- 期望：主流程 0 失败；网关重启后在线客户端收到积压通知
- 结果：☐

### 5. 停服务，守护不崩、恢复后补跑

- 状态：⛔ **阻塞**（等守护节点）
- 期望：守护退避重试；服务恢复后按截止时间补跑，不重复扣分
- 结果：☐

### 6. 管理端能停用座位、查预约、强制取消

- 状态：✅ 可验（管理端已提交，接口已就绪）
- 怎么做：管理端登录 → 座位管理停用一个座位 → 学生端确认不可约 → 强制取消一条预约
- 期望：停用后学生端看不到；强制取消后状态 CANCELLED 且座位释放
- 结果：☐

**当前进度：2/6 可验，4/6 阻塞。**
