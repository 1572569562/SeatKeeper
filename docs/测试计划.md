# 测试计划

| 项 | 内容 |
| --- | --- |
| 项目 | SeatKeeper 自习室座位预约系统 |
| 负责人 | 成员 8（质量与发布） |
| 版本 | v1.0（W2 基线） |
| 更新日期 | 2026-11-15 |

## 一、目标

1. 保证「预约 → 签到 → 超时释放 → 信用扣分」这条主闭环在四机环境下可演示、可重复。
2. 把「并发不超卖、重复调用不重复扣分」变成有证据的结论，而不是口头保证。
3. 让每次合并都能自动发现问题，而不是等到答辩前一天。

**不做的事**：不做 UI 自动化（JavaFX 界面手工验收）、不做安全渗透、不做超过 300 并发的容量测试。

## 二、测试分层

| 层次 | 测什么 | 工具 | 什么时候跑 | 谁负责 |
| --- | --- | --- | --- | --- |
| 单元测试 | 领域规则、参数校验、状态机 | JUnit 5 | 每次提交，CI 自动 | 各模块作者 |
| 集成测试 | 唯一索引、事务、幂等、并发抢座 | JUnit + 真实 MySQL（`-Pintegration`） | 每次 PR，CI 自动 | 成员 8 维护 |
| 接口冒烟 | 服务能否起来、鉴权是否生效、只读接口是否通 | `scripts/smoke-quick.ps1` | 每次部署后、演示前 | 成员 8 |
| 契约校验 | 接口实现与 `contracts/openapi.yaml` 是否一致 | 人工比对 + 冒烟脚本 | 接口变更时 | 成员 3 + 成员 8 |
| 端到端 | 预约→签到→过期→扣分→通知 | 手工脚本 + 种子数据 | 每周五、RC 前 | 全员 |
| 性能 | 200 并发抢座、座位图查询延迟 | JMeter | W7、W8 | 成员 8 |
| 故障演练 | 停服务、停网关、重启补跑补投 | 手工 + 录屏 | W7 | 成员 5、6、8 |

## 三、环境

| 环境 | 用途 | 说明 |
| --- | --- | --- |
| 本地开发库 | 单人开发 | `seatkeeper`，端口按各人配置（默认 3307） |
| 测试库 | 集成测试专用 | **库名必须以 `_test` 结尾**，测试会清表；`TestDatabaseGuard` 会拦非法库名 |
| 演示库 | 演示与答辩 | `seatkeeper` + `demo` profile，可反复重置 |
| 四机环境 | 端到端与故障演练 | A 服务+库、B 守护、C 客户端、D 网关 |

### 冒烟脚本有两个，别用错

| 脚本 | 运行环境 | 覆盖范围 | 什么时候用 |
| --- | --- | --- | --- |
| `scripts/smoke-quick.ps1` | Windows PowerShell 5.1 或 7 | 健康检查、座位/时段、鉴权拦截（6 项） | 每次部署后、演示前 |
| `scripts/smoke-member3.ps1` | **必须 PowerShell 7.2+** | 登录→预约→签到→批处理→管理端（全链路） | 每周五验收、RC 前 |

```powershell
# 快速检查（5.1 就能跑）
powershell -ExecutionPolicy Bypass -File scripts\smoke-quick.ps1

# 全链路（先装 PowerShell 7：winget install Microsoft.PowerShell）
pwsh -File scripts/smoke-member3.ps1
```

集成测试需要三个环境变量：

```bash
export SEATKEEPER_TEST_DB_URL='jdbc:mysql://127.0.0.1:3306/seatkeeper_test?serverTimezone=Asia/Shanghai'
export SEATKEEPER_TEST_DB_USER=root
export SEATKEEPER_TEST_DB_PASSWORD=你的密码
mvn -Pintegration verify
```

## 四、入口与出口准则

**开始测试（入口）**

- 代码能编译：`mvn -DskipTests package` 成功
- 数据库能建：Flyway 从空库迁移成功
- 冒烟脚本通过

**可以交付（出口）**

- 单元 + 集成测试全绿，0 失败 0 跳过
- 冒烟脚本 0 失败
- 6 条验收标准全部可演示（见《回归清单》）
- 无 P0 缺陷；P1 缺陷有明确处理结论
- 演示环境可重复搭建，备份视频已录制

## 六、当前阻塞（必须让全组知道）

| 阻塞项 | 影响 | 解除条件 |

**测试不能替代码兜底。** 上面四条没解除前，回归清单里对应项一律标「阻塞」，不要写「已通过」。

## 七、缺陷管理

用 GitHub Issues，标签：

- `bug/P0`：主流程走不通、演示会失败 —— 当天修
- `bug/P1`：次要功能异常或有明显体验问题 —— 本周内修
- `bug/P2`：不影响演示 —— 进 backlog

一个 issue 一条缺陷，写清「怎么复现、期望、实际、环境」。修完由提出人验证关闭，作者不能自己关。
