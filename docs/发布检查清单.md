# 发布检查清单

发布 = 打 tag、出安装包、能交付。每一步都要有结果，不能只写「差不多」。

## 一、代码

| # | 检查 | 命令 / 做法 | 标准 |
| --- | --- | --- | --- |
| 1 | main 是最新的 | `git pull --ff-only` | 无冲突 |
| 2 | 工作区干净 | `git status` | 没有未提交改动 |
| 3 | 没有测试代码进主分支 | `git ls-files \| findstr "IT.java"` | 只有 src/test 下的 |
| 4 | 没有密钥 | `git ls-files \| findstr "\.env$"` | 无输出 |
| 5 | 没有大文件 | `git ls-files \| findstr /i "mp4 zip jar"` | 无输出（target 已忽略） |
| 6 | 没有调试残留 | `git grep -n "System.out.println\|TODO\|FIXME"` | 关键路径无 |

## 七、打 tag

```bash
git tag -a v1.0.0 -m "课程项目交付版本"
git push origin v1.0.0
```

发布后如果还要改，只能出 `v1.0.1`，不能覆盖已有 tag。
