## 红绿回归与审查修复

1. 健康接口实现前，正式Maven编译因缺少HealthController失败；补齐后通过。
2. 临时移除预约version条件，旧版本更新测试断言实际失败；恢复后全量通过。
3. 旧通知实现允许第二笔同用户通知先提交，游标可能漏低ID；旧代码测试确实失败。修复为发送前锁credit行直至外层提交后，A未提交时B阻塞、查询不可见B，最终游标读到两条消息。
4. RR隔离下，两用户先取得缺键间隙锁再插入信用流水，旧代码实际出现死锁；显式采用RC并保留主键行锁、唯一键后回归通过。
5. 旧测试库包含匹配在无DB守卫测试中失败；改为严格后缀并同连接核验实际库后通过。
6. 模板和正式工程的V1内容不同，已使用独立库并在模板README明确不可混用历史。座位EXPLAIN也补为实际Mapper原样SQL。

独立只读审查复核确认上述重要问题均已处理，没有代码阻断项。
