# ADR-001：成员 3 服务端架构与业务规则

- 日期：2026-11-13
- 状态：已采纳（含 1 个开放问题）
- 范围：`seatkeeper-service` 业务层、`contracts/openapi.yaml`、全局错误码
- 依据：《SeatKeeper 团队执行手册》表 8（成员 3）、`docs/数据层交接.md`

## 1. 背景

成员 4 已交付 7 张表、生成列、两组活动唯一索引、四个持久化组件（预约 / 信用 / 通知 / 目录）
以及 33 项真实 MySQL 测试。数据层只保证"数据对不对"，明确留白五件事：

1. 用户认证与角色权限
2. 完整预约状态机
3. 签到截止时间计算
4. 扣分与信用限制判定
5. 对外 HTTP 接口

本 ADR 记录这五件事的落地方式，以及手册未规定、由成员 3 拍板的规则。

## 2. 分层与边界

```
api/          Controller：只做参数接收、身份读取、结果封装
service/      用例接口：业务规则、事务边界
service/impl/ 编排成员 4 的持久化原语
security/     密码哈希、JWT、拦截器
mapper/       只读查询补充（成员 4 的 Mapper 只增量新增方法）
model/        dto（入参）/ vo（出参）/ po（持久化）
```

规则：

- **Controller 不直接调 Mapper**（除现有 `HealthController` 的既有写法），一律经 Service。
- **PO 不出接口**：所有响应都是 VO，座位、时间、状态字段在 VO 层转成 `+08:00` 偏移。
- **只读查询可新增 Mapper 方法**，不修改成员 4 已有方法签名与 SQL。

## 3. 状态机

```
                 ┌──────────────┐
   创建 ────────▶│   RESERVED   │
                 └──┬───┬───┬───┘
        签到 ✔      │   │   │  取消
                    ▼   │   ▼
             ┌────────┐│ ┌───────────┐
             │CHECKED ││ │ CANCELLED │
             │  _IN   ││ └───────────┘
             └───┬────┘│
      时段结束 ✔ │     │ 过了签到截止仍未签到
                 ▼     ▼
          ┌──────────┐┌─────────┐
          │COMPLETED ││ EXPIRED │
          └──────────┘└─────────┘
```

- 只有 `RESERVED` 能签到、能取消；`CHECKED_IN` 只能等完成或由管理员强制取消。
- `CANCELLED / EXPIRED / COMPLETED` 是终态，不再迁移。
- 迁移一律带 `version` 条件更新，影响 0 行表示并发冲突，重新读取后再决策。

## 4. 决策清单

| 编号 | 决策 | 理由 | 依据 |
|---|---|---|---|
| D1 | 信用 **< 60 分** 时把 `restricted_until` 设为扣分时刻 + 7 天 | 100 分每次爽约 -10，4 次到 60；固定 7 天便于演示与解释 | 手册未规定 |
| D2 | "同时最多 2 个"在应用层 count 校验，不加用户行锁 | 手册只要求 200 并发抢**同一座位**不出错；锁用户行会牺牲并发 | 手册 1.2、表 8 W4 |
| D3 | 学生主动取消**不返还**信用 | 数据层交接明确"取消不自动返还" | `docs/数据层交接.md` |
| D4 | 管理员强制取消不扣分、不返还，发 `SYSTEM` 通知 | 是管理行为，责任不在学生 | 手册未规定 |
| D5 | `reason` 码：`NO_SHOW` / `SYSTEM_COMPLETE` / `ADMIN_ADJUST` / `CANCEL_REFUND` | 稳定、全大写、≤64 字符；幂等键依赖它 | 数据字典 |
| D6 | 签到窗口 `[slotStart, slotStart+15min]`，早到与迟到都拒绝 | 契约示例 08:00 → 08:15 | 手册 3.2 |
| D7 | 过期判定：`status=RESERVED 且 check_in_deadline < now` | 守护节点 30 秒扫一次，最迟延迟 30 秒 | 手册表 1 |
| D8 | 完成判定：`status=CHECKED_IN 且 slot_end < now` | 成员 5 表 W6 | 手册表 10 |
| D9 | 通知类型四类：`RESERVATION / CHECKIN / CREDIT / SYSTEM` | 种子数据已用前两类，向后兼容 | 手册未规定 |
| D10 | 内部接口用共享密钥 `X-Internal-Token`，常量时间比较 | 内部调用没有用户身份，复用 JWT 不合适 | 手册 2.1 |
| D11 | 网关不直连 MySQL，改走内部只读接口 `GET /api/v1/internal/notifications` | MySQL 仅监听 A 机本机，D 机连不上；铁律一禁止跨机直连 | 手册表 1、2.1 |
| D12 | 座位停用后拒绝新预约（409 `SEAT_DISABLED`），已有预约保留 | 强制取消已有预约会伤学生，管理员可手动处理 | 手册表 12 |
| D13 | 只能预约尚未开始的时段（`slot_start > now`） | 允许预约已经开始的时间段没有业务意义 | 手册未规定 |
| D14 | 分页默认 20、最大 100 | 与数据层 1..1000 上限兼容，够用且防止大页 | 手册未规定 |
| D15 | 满 100 分时跳过加分但仍置 `COMPLETED` | `applyDelta` 越界会拒绝并回滚，重试会打爆守护节点 | 数据层 `CREDIT_OUT_OF_RANGE` |

## 5. 认证方案

- **密码哈希**：PBKDF2-HMAC-SHA256，12 万次迭代，16 字节随机盐，常量时间比较。
  存储格式 `pbkdf2$迭代$盐$摘要`，与 `app_user.password_hash VARCHAR(255)` 兼容。
  选它而不选 BCrypt 的原因：不引入 `spring-security-crypto` 依赖，JDK 自带。
- **令牌**：HS256 JWT，载荷 `sub/role/iat/exp`，默认 8 小时有效期，密钥 ≥32 字节否则启动失败。
  选它而不选 `jjwt` 的原因：同样避免新增依赖，签名与校验逻辑不足百行。
- **鉴权位置**：`HandlerInterceptor`，`/api/v1/health`、`/auth/login`、`/internal/**` 放行，
  `/admin/**` 额外要求 `ADMIN` 角色；用户身份以 `CurrentUser` 方法参数注入，不从请求体读取。
- **登录错误统一**为 `401 UNAUTHORIZED`，不区分"学号不存在"与"密码错误"，避免枚举账号。

## 6. 批处理语义

- 每条预约一个独立事务（`TransactionTemplate`），单条失败不影响同批其他记录。
- 幂等两层：状态条件更新 + `credit_log(reservation_id, reason)` 唯一键。
- `failed` 的记录下一轮会被重新扫描，因此必须保证重试不产生副作用。
- `expire-batch`：置 `EXPIRED` → 扣 10 分 → 低于 60 分则限制 7 天 → 发 `CREDIT` 通知。
- `complete-batch`：置 `COMPLETED` → 未满 100 分加 1 分 → 发 `CREDIT` 通知。
