# SeatKeeper 运维说明（成员4 W7—W8）

适用范围：单机 MySQL 8.0、Spring Boot 服务、专用演示/测试库的备份、恢复和演示重置。生产登录、四机通信、JavaFX 与节点守护进程须由对应成员联调。所有命令在项目根目录执行，脚本要求 PowerShell 7.2+；PowerShell 文件使用 UTF-8 BOM。

## 1. 环境与凭据

```powershell
Copy-Item .env.example .env
# 用编辑器替换 .env 中的 CHANGE_ME 占位值，再执行下文命令。
```

只提交 `.env.example`；`.env` 和 SQL 备份不进入版本库。`MYSQL_ROOT_PASSWORD` 与 `MYSQL_PASSWORD` 是不同用途的凭据；`DB_USER`/`DB_PASSWORD` 要与应用账号一致。`.env` 支持字面量 `KEY=value` 和整行注释，不执行命令或变量替换，已有进程环境变量优先。不要把密码写入 `-p...` 参数、SQL 或终端历史。

Spring Boot 本身不读取 `.env`。下列命令通过脚本中与运维工具相同的加载函数明确导入，再启动服务：

```powershell
. ./scripts/mysql-common.ps1
Import-ProjectEnvironment | Out-Null
$env:SPRING_PROFILES_ACTIVE = 'demo'
java -jar ./seatkeeper-service/target/seatkeeper-service-1.0.0-SNAPSHOT.jar
```

也可在启动进程前由部署系统直接设置 `DB_URL`、`DB_USER`、`DB_PASSWORD`，不使用 `.env`。服务默认监听 `127.0.0.1:8080`。第一次 demo 启动使用 Flyway 扫描 `db/migration` 和 `db/demo`；普通配置只扫描结构迁移。`V1__schema.sql` 为结构，`V2__demo_data.sql` 为独立演示数据，已执行版本的文件不能修改。

## 2. Docker MySQL

Compose 固定官方 `mysql:8.0.44`，命名卷保存 `/var/lib/mysql`，健康检查使用容器现有的 root 环境变量。所有宿主端口仅绑定回环地址：

```powershell
docker compose --env-file .env -f deploy/compose.mysql.yml config --quiet
docker compose --env-file .env -f deploy/compose.mysql.yml up -d
docker compose --env-file .env -f deploy/compose.mysql.yml ps
docker compose --env-file .env -f deploy/compose.mysql.yml logs --tail 100 mysql
# 正常停止并保留卷
docker compose --env-file .env -f deploy/compose.mysql.yml down
```

本地端口默认 `127.0.0.1:3307`，避免占用已有 MySQL 3306。四机手册要求数据库所在服务器使用 3306 时，将 `.env` 的 `MYSQL_PORT` 改为 `3306`，对应映射仍为 `127.0.0.1:3306:3306`；服务的 `DB_URL` 同步改为回环 3306。其他机器不能直接访问该端口；跨机访问方式由团队联调约定，不通过修改本文件开放公网。

Compose 的初始化账号/库环境变量只在空数据卷首次启动时生效。修改 `.env` 不会自动修改已有卷中的账号密码。不要使用 `down -v` 来重置演示数据；使用第5节的受限重置脚本。

本机最初在默认沙箱检查中无法访问 Linux Engine 命名管道，桌面启动命令也未找到注册项；这属于当时权限和启动入口的检查结果。随后使用正常本机权限启动已有 Docker Desktop，`mysql:8.0.44` 容器已达到healthy，并完成下文Docker模式的真实重置、备份恢复和六组EXPLAIN验收。没有把Compose静态配置检查当作容器运行证明。Native的独立回环MySQL 8.0.34验收记录仍单独保留。

## 3. 脚本连接参数

| 参数 | 默认/作用 |
| --- | --- |
| `-Mode Native` / `-Mode Docker` | Native 调用本机工具；Docker 通过此 Compose 的 `mysql` 服务执行容器工具 |
| `-Database` | 一般取 `MYSQL_DATABASE`，缺省 `seatkeeper`；恢复必须显式指定；重置默认 `seatkeeper` |
| `-HostName` / `-Port` | Native 默认 `127.0.0.1` 和 `MYSQL_PORT`/3307；Docker 固定容器内回环3306 |
| `-User` | `MYSQL_USER`/`seatkeeper`；管理恢复可明确选 root，推荐仅对目标库有权限的专用账号 |
| `-MysqlBin` | Native 工具目录，默认 `MYSQL_BIN` 或 PATH；需包含 mysql.exe 与 mysqldump.exe |
| `-EnvFile` | 默认项目根 `.env`；缺失时使用已有进程环境 |

Native 密码仅注入子进程的 `MYSQL_PWD` 环境，优先读取已有 `MYSQL_PWD`，否则 root 读取 `MYSQL_ROOT_PASSWORD`，应用账号读取 `MYSQL_PASSWORD`。Docker 工具读取容器现有凭据。脚本不打印密码。若账号密码不同于 `.env`，在专用终端进程设置对应变量并在使用后清除。

## 4. 备份与恢复

```powershell
New-Item -ItemType Directory -Force ./backups | Out-Null
./scripts/backup.ps1 -Mode Native -Database seatkeeper -OutputFile ./backups/demo-before.sql
# Docker 同样使用 -Mode Docker，无需宿主 mysql.exe
# ./scripts/backup.ps1 -Mode Docker -Database seatkeeper -OutputFile ./backups/docker-demo.sql

# 目标专用库须事先创建，连接账号只授予该库权限。恢复会替换同名表。
./scripts/restore.ps1 -Mode Native -Database seatkeeper_test -InputFile ./backups/demo-before.sql -ConfirmRestore
```

备份采用 `--single-transaction --no-tablespaces --set-gtid-purged=OFF`，不带 `--databases`，不生成 CREATE/USE DATABASE。备份包括结构、七张业务表和 Flyway 历史；没有事件、触发器和存储例程。生成期间不要执行 DDL 迁移。SQL 从 mysqldump stdout 以原始字节写入同目录临时文件，退出成功后原子改名，并输出 SHA-256；已有目标文件会拒绝覆盖。不会使用 PowerShell 默认 `Out-File` 改变 SQL 编码。

恢复仅接受项目库 `seatkeeper` 或以 `_test` 结尾的测试库和明确的 `-ConfirmRestore`，并拒绝库切换、跨库限定引用等脚本。只恢复由本脚本产生且来源可信的单库备份；恢复账号应仅有目标库权限。UTF-8 输入以原始字节流送入 mysql，不走 `Get-Content | mysql`。恢复涉及 DDL，不能承诺整文件回滚；开始前保留目标库旧备份，停止写入，失败后检查错误并用旧备份恢复。

## 5. 可重复演示重置

```powershell
./scripts/reset-demo.ps1 -Database seatkeeper -DemoDate 2030-01-15 -ConfirmReset
./scripts/reset-demo.ps1 -Mode Docker -Database seatkeeper -DemoDate 2030-01-15 -ConfirmReset
```

先完成 Flyway 建表；不在真实业务库运行。重置只执行七表的明确 DELETE，依次为 `credit_log`、`notification`、`credit`、`reservation`、`slot`、`seat`、`app_user`，在同一事务中重放原版 V2 种子。不使用 Flyway clean、不禁用外键、不删除或改写 `flyway_schema_history`，也不执行 DROP DATABASE。

默认日期固定为 `2030-01-15`，显式主键与所有业务日期时间均固定；相同 `-DemoDate` 两次运行可得到完全相同的业务行、键和时间。种子总数为3用户、8座位、7时段、2预约、3信用、1流水、2通知。七个时段为演示日08/10/12/14/16/18/20点开始，每段2小时。没有可登录的演示密码；账号 `password_hash` 为禁用占位值。

DELETE 不重置 InnoDB AUTO_INCREMENT 计数器；这不会改变显式种子行的一致性，也避免为计数器执行破坏事务边界的 ALTER TABLE。重置时应暂停业务写入。

## 6. 运行检查与验收记录

```powershell
pwsh -NoProfile -File ./scripts/tests/test-guards.ps1
pwsh -NoProfile -File ./scripts/tests/test-restore-scope.ps1
pwsh -NoProfile -File ./scripts/tests/test-relative-paths.ps1

pwsh -NoProfile -File ./scripts/tests/test-roundtrip.ps1 -Database seatkeeper -ConfirmReset
./scripts/explain.ps1 -Database seatkeeper -OutputFile ./backups/explain.txt
```

参数拒绝检查无需数据库，覆盖生产库名、缺少确认开关和注入式库名。跨库SQL检查还覆盖未引用/反引号限定表名、同一行的USE和MySQL可执行注释中的删库语句。Native进程检查也不连接数据库，核对两个工具的stdout未混入进程层内部对象。roundtrip集成验证比较两次固定日期重置后的七表数据SQL，再修改一条中文通知并从备份恢复，同时逐字段核对完整Flyway历史；备份保留在 `scripts/tests/artifacts/` 供核查。EXPLAIN 的查询、预期索引和实际结果见 [EXPLAIN检查.md](EXPLAIN检查.md)。
