# 成员 3 一页架构说明

## 1. 进程与端口

| 进程 | 机器 | 端口 | 职责 | 负责人 |
|---|---|---|---|---|
| 预约服务 `seatkeeper-service` | A | 8080 | 唯一能写业务表的服务 | 成员 3 / 4 |
| MySQL 8.0 | A | 3306（仅本机） | 7 张业务表 + Flyway 历史 | 成员 4 |
| 守护节点 `seatkeeper-guardian` | B | 无入站 | 每 30 秒调用内部批处理接口 | 成员 5 |
| 通知网关 `seatkeeper-gateway` | D | 8082 | 会话与投递，经内部接口读通知 | 成员 6 |
| 学生端 / 管理端（JavaFX） | C | — | 只调 `/api/v1/*` | 成员 1、2、7 |

铁律不变：**只有预约服务写业务表**；守护节点与网关不得直连数据库改数据。

## 2. 服务内部分层

```
api/         Controller —— 只接收参数、取 CurrentUser、封装 Result
service/     用例接口 —— 业务规则、@Transactional 事务边界
service/impl/ 编排成员 4 的持久化原语（Reservation/Credit/Notification/Catalog DataService）
security/    PasswordHasher(PBKDF2) + JwtService(HS256) + 两个拦截器
mapper/      MyBatis 接口（在成员 4 基础上只增量补只读查询）
model/       dto 入参 / vo 出参 / po 持久化，PO 不出接口
```

## 4. 三条主链路

**预约闭环**

```
客户端 POST /reservations
  → 校验时段命中 slot、未开始
  → 校验座位存在且 AVAILABLE
  → 校验信用未受限
  → 校验同时预约 < 2
  → create() 直接 INSERT（唯一索引裁决冲突 → 409 SEAT_TAKEN）
  → 同事务写 notification(type=RESERVATION)
```

**超时释放（守护节点每 30 秒）**

```
POST /internal/reservations/expire-batch
  → 扫描 RESERVED 且 check_in_deadline < now
  → changeStatus(EXPIRED) + applyDelta(-10, NO_SHOW)
  → 低于 60 分 → updateRestriction(now + 7 天)
  → 发 CREDIT 通知
```

**通知投递（网关）**

```
网关轮询 GET /internal/notifications?userId=&afterId=
  → 保存 lastId 作为下一轮游标
  → 推给在线会话（W6 切 WebSocket）
客户端断线重连 → 用同一游标补拉，不丢消息
```

## 5. 配置项

| 配置 | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| 数据库地址 | `DB_URL` | 本机 3307 | 演示用 3307，部署改 3306 |
| 令牌密钥 | `JWT_SECRET` | 开发默认值 | **四机部署必须覆盖**，≥32 字节 |
| 内部密钥 | `INTERNAL_TOKEN` | 开发默认值 | 守护节点与网关共享 |
| 演示密码 | `DEMO_PASSWORD` | `Demo@123456` | 仅 `demo` profile 建号用 |

## 6. 已知限制

1. 管理端信用调整**必须绑定该用户的一条预约**（表 3 的 `reservation_id NOT NULL` 与 `uk_credit_res_reason` 决定）：
   学生没有预约时无法调整；同一预约同一原因只能调一次。
2. 预约端口 8081 未使用（手册未说明用途）。
3. 早到不能签到，签到窗口从 `slotStart` 开始。
4. 管理端查预约走 `JOIN`，数据量大时需补索引与分页优化（W7 压测时确认）。
